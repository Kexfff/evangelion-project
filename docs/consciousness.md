# Consciousness, initiative and reminders

Minecraft's **Independent gameplay** controls are separate: disabling or pausing companion Consciousness, quiet hours and its daily limits do not stop gameplay. Use the Minecraft gameplay Pause/Stop controls when needed. System lock/suspend and global emergency stop still stop game activity; see [Minecraft autonomy](minecraft.md#independent-gameplay-v0412).

[← Documentation](README.md) · [Project home](../README.md)

This is an inspectable **behavior simulation**, not actual sentience. Mood, boredom, energy, trust and affinity persist per character and influence tone and avatar expressions. The state editor explains each update rule and lets you adjust values and bounds. Absence does not lower relationship values. Idle drift is capped at six hours per update; no background LLM call is needed to update state.

1. In **Consciousness**, set your **IANA time zone** (default UTC; for example `Europe/Moscow`), quiet hours, cooldown and daily budget. Save changes.
2. Enable **autonomy** to permit scheduled reminders. Separately enable **conversation openers** if you want unsolicited chat. Both start off. Openers require the idle threshold, sufficient boredom and energy, and positive initiative. A default initiative of 40 means boredom must reach 60; it does not promise a message exactly at the idle threshold.
3. Create a reminder with an exact ISO timestamp containing `Z` or an offset, such as `2026-09-13T18:30:00+03:00`. Creating it in settings authorizes it. Times must be in the future and within one year. The task manager shows the persistent ID, UTC instant, supplied time-zone label, status and outcome. Cancel tasks there.
4. Optionally enable **LLM scheduling tools** and choose a tool-capable model. The model can propose, list and cancel reminders via the [OpenRouter-compatible function-calling protocol](https://openrouter.ai/docs/guides/features/tool-calling). **Every LLM-created task needs your approval in Consciousness before it is armed.** For compatibility, tools-enabled user replies use a bounded, non-streaming loop (at most four LLM requests); intermediate planning/tool JSON is never spoken. Disabling scheduling tools restores normal streamed chat. Autonomous turns cannot schedule more actions.
5. Keep the companion visible and idle for desktop delivery, or enable the paired Telegram notification channel described below. Typing or an image draft, recording/hands-free listening, generation, queued/playing audio, system lock/suspend, quiet hours and manual pause defer autonomous actions. Missing renderer heartbeats/minimization defer desktop delivery but do not prevent an available Telegram channel from delivering. Fresh busy presence still blocks Telegram notifications even if minimized. No desktop observation detects other apps: use **Pause autonomy** in the avatar title bar when busy elsewhere. Desktop input preempts an autonomous reply. Settings changes cancel an in-flight generation before applying.

The internal clock checks every five seconds while the app runs. It does not run when the app is closed or wake a sleeping/powered-off PC. Only the active character delivers actions. Cooldown and the local-calendar daily budget apply to both reminders and openers; failed attempts count too. Quiet hours may cross midnight; equal start/end means quiet all day. After resume/restart, pending reminders inside the catch-up window wait for a safe opportunity; older ones become `missed`. A task claimed before a crash becomes `failed`, never automatically replayed: at-most-once attempts avoid duplicate reminders but cannot guarantee delivery during a crash. Cancelled/failed/missed tasks can be recreated manually. `done` means the reply was saved, not that audio was heard.

The activity log records policy changes, reasons, task outcomes, LLM request counts and provider-reported tokens/costs. Missing usage is marked **not reported**, never estimated as free. Audio/embedding charges and provider connection tests are not part of this log. Memory extraction has separate request/usage events. State, tasks (maximum 2,000 retained), and a rolling 500-entry activity log live in `companion.json`; snapshots and the settings UI initially load only the latest **10 character-scoped events**. **Older 10** fetches another page on demand; **Latest 10** returns to live activity. This changes presentation, not retention. **Memory exports do not include tasks, behavior state or plugin configuration**, and importing memory cannot arm tasks or enable integrations. Deleting chat history does not cancel reminders or clear behavior; use the task manager/global pause for that. [MCP tools](mcp.md) are available to user-requested conversations, but proactive/scheduled tool execution and game/PC actions remain future work.

## Diagnosing failed autonomous replies (v0.4.21)

**v0.4.22 compatibility fix:** Autonomy instructions now stay in the initial system prompt, followed by a request-only, explicitly application-authored trigger after the conversation. This fixes the empty completions reproduced with DeepSeek through OpenRouter when the request ended in a system message. Both openers and reminders are covered; no synthetic human message is saved. Restart the updated app to load the fix. Existing cooldowns and daily attempt counts remain unchanged, so a previous failure may still defer the next attempt.

Expand **Diagnostic details** on a new autonomous event. An attempt ID connects request, saved-reply, completion or failure events. Metadata records the stage (context, credentials, provider, save, delivery or events), elapsed time, model, provider hostname, explicit OpenRouter routing when configured, destination, streaming/token-limit settings, message roles (not content), first-text timing and received character count. Saved/delivered flags distinguish a failed generation from a notification failure after the reply was already saved. Successful handoff does not prove audio playback completed.

Failures distinguish HTTP status, provider stream errors, missing/truncated/malformed responses, timeouts, selected network/TLS codes, local cancellation and unclassified local errors. Safe structured failure metadata also appears in the desktop process console under `[autonomy]`, even if persisting the failure log subsequently fails. Diagnostics do not log API keys, prompts, generated text, arbitrary exception messages/stacks or raw provider bodies. Unknown errors remain generic rather than exposing private data. This diagnostic release does **not** change autonomous prompt layout, routing, retries, cooldowns or budgets.

Use **Consciousness → Activity log → Export all logs** to choose a JSON file. It includes **all retained activity across all characters**, app version, OS/architecture and export time—not only the current page, and not the full console log. Cancelling the dialog writes nothing. Existing event descriptions may contain reminder titles or other personal labels: review the file before sharing. Export is separate from memory archives and does not modify or clear activity.

Old generic failure entries cannot gain missing diagnostics retroactively, and entries already evicted from the rolling 500-event log cannot be recovered. On an affected machine, run the updated build, let a fresh failure occur, then export promptly. No remote PC access is needed to inspect that file initially.
